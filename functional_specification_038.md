## 1. System Purpose & Core Objective

This specification defines the desired `{functionality}`, 3D asset decimation and normal-generation pipeline, spatial coordinate schedules, live 60 FPS OLED `CanvasTexture` mounting contract, interactive 3D button and switch raycasting/depression mechanics, 360° 3D inspection behavior, operational and performance budgets, edge-case failure boundaries, and verifiable `{correct required outputs}` for upgrading the Freeman Alley **"DOOM TRACKS" (`SYS-990-AMBER // AUDIO SYSTEM v2`) MP3 Player** to use the 3D hardware asset [`/Users/diesel/Desktop/SkateAlley/audiodevice.glb`](file:///Users/diesel/Desktop/SkateAlley/audiodevice.glb).

This specification builds upon and extends [`functional_specification_035.md`](file:///Users/diesel/desktop/skatealley/functional_specification_035.md) and [`doom_tracks_mp3_hud.js`](file:///Users/diesel/desktop/skatealley/doom_tracks_mp3_hud.js).

The primary objective is to instruct a coding assistant to:
1. **Decimate and Optimize [`audiodevice.glb`](file:///Users/diesel/Desktop/SkateAlley/audiodevice.glb) Prior to Runtime Use**: Reduce the raw 40,000-triangle, 3.99 MB single-mesh glTF asset (which currently lacks vertex normals and embeds an uncompressed 2.97 MB `2048 × 2048` PNG texture) into a lightweight, production-grade decimated 3D asset (`audiodevice_decimated.glb`, target $\le 6,000$ triangles, authored smooth vertex normals, WebP/PNG optimized texture encoding, $\le 350\text{ KB}$ total payload, perceptual $\text{SSIM} \ge 0.96$).
2. **Orient & Brand the 3D Audio Device (`"DOOM TRACKS"`)**: Transform the portrait-authored [`audiodevice.glb`](file:///Users/diesel/Desktop/SkateAlley/audiodevice.glb) mesh via a $-90^\circ$ roll around $+Z$ (`rotation.z = -Math.PI / 2`) into its canonical horizontal landscape deck orientation (`1.995 m` wide $\times$ `1.390 m` tall $\times$ `0.238 m` thick), and replace the top-center nameplate label `"TECHNO-AUDIO"` with **`"DOOM TRACKS"`** in identical `#ffa51d` extended techno-industrial typography while preserving the surrounding rules and bevels.
3. **Mount the Live 60 FPS Amber OLED Screen onto the 3D Asset**: Seat the live 60 FPS dynamic Amber OLED display (`▶ PLAYING` / `❚❚ PAUSED` / `■ STOPPED` banner, scrolling `« SONG TITLE »` marquee, interactive seek/progress bar, spinning optical CD icon, real-time Web Audio `AnalyserNode` oscilloscope waveform, animated dual-reel cassette hubs, `TIME ELAPSED` `MM:SS` digital clock, 10-segment rising `VOLUME` bar meter, reactive $8 \times 5$ FFT dot-matrix frequency grid, and `128 KBPS` / `MP3 / STEREO` telemetry) directly inside the recessed 3D screen cavity of the decimated `audiodevice` model (`Z_local ≈ +0.0892 m`), supporting direct 3D UV-raycasted scrubbing and toggles on the screen surface.
4. **Make All 3D Hardware Buttons & Switches Interactive (Without Emissive Rim Highlights)**: Enable direct 3D raycast interaction and physical mechanical depression along $-Z_{\text{local}}$ across all 7 molded 3D transport buttons (`PLAY`, `PAUSE`, `STOP`, `REPEAT/CYCLE`, `PREV`, `NEXT`, `PLAYBACK`) and 2 mid-deck slide switches (`SHUFFLE`, `LOOP / VISUALS`), plus 3D chassis tilt/orbit inspection so the user can view the detailed `PLATODOOM-INC // MODEL NO: SYS-990-AMBER` rear armor plate. Per explicit user directive, interactive 3D buttons and switches must **NOT** render an amber emissive rim highlight on hover, press, or active state.
